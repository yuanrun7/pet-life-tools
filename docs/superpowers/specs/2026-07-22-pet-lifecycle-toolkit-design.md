# 宠物全生命周期纯工具平台设计说明

日期：2026-07-22  
状态：已完成分段确认，待用户审阅书面规格

## 1. 产品目标

建设一个面向中国猫狗宠主的多页面静态 PWA。平台不卖货、不展示广告、不加载追踪脚本，以真实可用的工具和搜索流量验证需求。首版不购买服务器，所有计算在浏览器内完成，用户数据仅保存在本机。

原方案中的“全网无竞品”“工具层完全空白”不作为宣传依据。公开市场已经存在单点疫苗、成本和寻宠海报工具。首版差异化调整为：中文场景、零商业干扰、规则透明、多个工具与本地宠物档案打通。

## 2. 目标用户与成功标准

核心用户为养猫、养狗 0—3 年的新手宠主，其首要任务是快速得到可信排期、预估养宠成本、制作寻宠海报并保存宠物记录。

首版成功标准：

- 五个工具在手机和电脑端均可完成完整流程。
- 每个工具拥有独立静态网址、标题、说明、FAQ 和结构化数据。
- 用户无需登录即可使用；档案刷新后仍存在，并可备份和恢复。
- 核心计算有自动化测试；生产构建和移动端、桌面端浏览器验收通过。
- 页面不含广告、带货、第三方追踪或远程字体，首次加载资源目标约 500 KB。

## 3. 首版范围

### 3.1 首页

展示品牌定位、今日待办、五个工具入口、数据隐私提示和纯工具承诺。未建立档案时引导用户创建宠物档案；已有档案时优先展示近期健康事件。

### 3.2 疫苗与驱虫排期

输入宠物类型、生日、既往记录和生活环境，基于版本化规则生成时间线。用户可手动修正记录、保存至档案、下载 `.ics` 日历。结果必须显示规则版本、更新时间、适用范围以及“由执业兽医确认”的提示。

首版不承诺品种级精准医疗，不根据地域自动下结论，不把规则生成包装成 AI 诊疗。

### 3.3 养宠成本计算

费用分为一次性支出、每月支出、每年支出和医疗备用金。所有默认金额可修改。输出月均成本、年度成本和预计生命周期成本，并区分刚需与可选消费。默认市场金额仅作为可编辑模板，不宣称实时市场均价。

### 3.4 寻宠海报

用户上传照片并填写走失时间、地点、特征、联系方式和悬赏信息。浏览器 Canvas 生成朋友圈版和 A4 打印版，支持下载图片。首版不实现 AI 抠图或画质修复；照片默认不长期保存。

### 3.5 宠物档案

支持多宠资料、疫苗驱虫记录、费用记录、纪念日和本地待办。提供 JSON 全量备份与恢复。页面明确说明清除浏览器数据会丢失档案，不宣传跨设备同步。

### 3.6 养宠问答

采用本地知识库、关键词检索和风险分流，覆盖常见饮食禁忌、日常护理和就医判断。出现呼吸困难、抽搐、持续出血等红旗症状时直接建议联系动物医院，不继续给出居家方案。内容不构成诊断，不提供处方或药物剂量。

## 4. 明确不做

首版不含账号、云同步、微信消息、在线支付、会员、B 端后台、小程序、远程大模型和需要服务端保密密钥的第三方 API。静态网页关闭后无法主动推送提醒，仅提供本地待办和日历导出。

## 5. 视觉与交互

采用已确认的“温暖编辑感”：米白为底色，苔绿与陶土色作为功能色；标题具有编辑排版感，正文保持高可读性。界面使用克制的圆角和留白，不采用高饱和卡通风，也不模仿医院后台。

所有工具遵循“填写信息 → 即时预览 → 保存档案 → 导出或分享”的一致流程。手机端使用底部导航，桌面端使用顶部导航；主任务目标在三步内完成。医疗风险使用独立高对比警示样式，不能被品牌暖色弱化。

## 6. 技术架构

采用 Vite、React 和 TypeScript，构建后输出可部署到免费静态托管的文件。PWA Service Worker 缓存核心资源，使首次加载后可离线使用主要工具。

模块边界：

- `rules`：疫苗、驱虫和风险分流规则及版本信息。
- `calculators`：日期和成本计算纯函数。
- `storage`：本地数据读写、模式版本、迁移、备份和恢复。
- `poster`：Canvas 海报排版和图片导出。
- `knowledge`：本地知识条目、标签、风险等级和检索。
- `pages` / `components`：独立页面和共享界面组件。

核心数据对象：

- `PetProfile`：身份、类型、生日、品种、性别、绝育状态、领养日期。
- `HealthEvent`：疫苗、驱虫、体检或自定义事件及日期。
- `ExpenseRecord`：分类、金额、日期、刚需标记和备注。
- `Reminder`：关联宠物、日期、类型和完成状态。
- `KnowledgeEntry`：标题、关键词、正文、风险等级和就医条件。

## 7. 数据流与隐私

表单输入先在内存中校验和预览，用户主动保存后才写入 `localStorage`。备份功能导出包含模式版本的 JSON；恢复时先验证结构，再让用户确认覆盖或合并。图片仅在当前页面内存和 Canvas 中处理，除非用户主动下载，否则不持久化。

平台不上传用户输入、不使用统计追踪、不请求通讯录或定位权限。若未来接入云端功能，必须另行设计隐私政策、账号体系和数据删除能力。

## 8. 错误与降级

- 缺失字段、未来生日、相互冲突的日期和异常金额均在提交前提示。
- 无效或版本不兼容的备份文件不得写入本地数据。
- 存储空间不足时提示用户先备份，并允许清理旧记录。
- Web Share API 不可用时改为下载文件；PWA 安装不可用时不显示安装入口。
- 海报图片解码失败时保留文字内容并要求重新选择图片。
- 规则无法覆盖的情况不猜测，明确提示咨询执业兽医。

## 9. SEO 与内容策略

每个工具拥有独立可抓取页面及针对搜索意图编写的标题、简介和 FAQ。首页聚合品牌词与工具入口，工具页聚焦“宠物疫苗时间表”“养宠成本计算器”“寻宠启事生成”等单一意图。内容不得使用“国内首个”“全网唯一”等不可证实表述。

首版不大量铺设泛科普文章。先通过工具使用率、导出率和用户反馈验证需求；由于不使用追踪脚本，初期可通过搜索平台站长工具数据和主动反馈观察效果。

## 10. 测试与验收

- 单元测试覆盖日期边界、年龄阶段、既往记录、零值和异常金额。
- 存储测试覆盖新增、修改、删除、模式迁移、备份、恢复和损坏文件。
- 海报测试验证朋友圈与 A4 尺寸、中文换行和超长文本。
- 端到端测试覆盖五个工具的主要路径和降级路径。
- 在常见手机宽度和桌面宽度进行截图检查，验证导航、表单、结果和警示信息。
- 运行类型检查、自动化测试和生产构建；仅在全部通过后交付。

## 11. 后续阶段

真实用户验证后，再依次评估：内容扩充、更多物种、云同步、微信小程序、服务端 AI 和 B 端工具。任何新增阶段都需独立评估成本、医疗合规、隐私和数据来源，不进入本次实现范围。
